一、背景：为什么是「金融文本」与「做市商视角」

演讲由 Citadel Securities 的两位同事完成。主讲人 Dianqi Li 把自己的研究定位为：把大语言模型（LLM）引入金融交易中最难啃的一块——复杂、高噪声、多模态、跨来源的金融文本数据。

二、核心议题（一）：系统化 / 半系统化交易是怎么运作的

  • Alpha 研究（X → Y）：X 是各类数据（历史价、订单簿、文本等），Y 是价格变动；模型对 Y 的合理预测即为 Alpha（超额收益）。
  • 半系统化交易 = 人在回路（Human-in-the-loop）：系统化侧产出信号，交易员基于强先验做调整，触发相反信号；这些人工调整本身又被收集为标签，反哺、提升系统化信号——形成类似现代 RLHF 的闭环。
  • 数据全景与根本差异：可预测的价格（Y）受历史价、订单簿、文本、第三方数据、图像、天气等影响。与科技行业相比，金融另有两个硬约束：信噪比极低 与 信息不公开 / 难获取。

三、核心议题（二）：金融文本数据的难点与「精度—召回」权衡

  • 三大难点：特征复杂、跨度长、任务多样；对应信噪比低、类型异构、可见度低且更新滞后。
  • 来源全景：新闻、社媒、财报电话会、SEC 备案、财报、专利、公告、研报、庭审记录……很多公开度低、非结构化、领域术语晦涩（EPS、META 与代码 AAPL、IV 隐含波动率等）。
  • 传统 NLP vs LLM：传统 NLP 上限等于写规则的人；LLM 数据驱动、长上下文、zero/few-shot，能把多个任务合并进单一模型。领域适配靠 continual pre-training / SFT / RLHF。
  • 最重要的一点始终没变：让 LLM 理解「交易逻辑」与「我们到底在找什么」——human prior 仍是关键。文本理解分两层：① 字面意思；② 字面背后的交易逻辑。

四、核心议题（三）：不能让 LLM「直接说买」——要先把先验喂进去

1. 交易模拟（以「X / 苹果」EPS 为例）

逐条新闻按时间推进：财报发布（无信息）→ EPS 高于去年（买还是卖？取决于市场预期）→ 跳涨 10%（通常已无信息量）。很多公司在业绩差时措辞也很委婉、负面信号很隐晦。因此正确做法是先把 human / trading prior 转成 LLM 能懂的语言，再组合成最终交易决策。

2. RAG 与幻觉治理

团队大量使用 RAG 来规范 LLM 输出、抑制幻觉。但讲者指出金融特有的坑：传统 RAG 按「时序/顺序」检索，而股市多标的并发、非时序——graph RAG（图检索） 可能是更优解，但仍属开放问题。

五、多模态、时间序列，与「金融 Agent」的展望

  • 表格解析：多模态模型把表格转成 tags，或走「区域检测 + OCR / 视觉模型」多阶段方案；高质量训练数据不足时可用合成数据策略。
  • 时间序列 + 语言的对齐难题：目前没有好的时间序列基础模型，也没有好的「时间序列 + 语言」多模态模型（跨域分布漂移极大）。
  • 金融 Agent：交易员想查「Rivian 下季度交付量」这类信息，Agent 在数据库里检索并回喂给交易员，时间就是机会（比竞争对手早一步拿到信息即盈利）。

🧭 核心框架：LLM 在金融文本的"辅助"定位

` 原始文本 → 注入 human/trading prior → RAG 检索（graph RAG?） → LLM 解读 → 信号（辅助） → 人在回路校准 → 交易决策（不替代） ` 关键约束：精度优先（报单方向错 = 直接亏钱）；human prior 不可省；非文本市场数据必须自建。

六、关键结论与趋势

1. LLM 在金融文本上的价值是「辅助 + 组织」，不是「替代决策」：human / trading prior 是绕不开的约束条件。 2. RAG 是当下最务实的落地形态，但金融多标的、非时序的特性让 graph RAG 成为值得探索的方向。 3. 时间序列 + 语言的多模态是尚未解决的基础难题，也是金融场景区别于通用 NLP 的核心壁垒。 4. 金融 Agent（检索 / 提炼 / 回喂） 是把 LLM 能力转化为交易实效的自然载体，时间敏感度是胜负手。 5. 文本问题可站在公开基线上；非文本市场数据必须自建模型——这是机构相对开源社区的真实护城河。
