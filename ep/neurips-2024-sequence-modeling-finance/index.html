  • 核心洞察：消费银行客户的数据本质是"多个事件流的交织"（transaction / payment / digital activity / return），temporal ordering 不是装饰，是业务——但行业现实仍以树模型（XGBoost/LightGBM）为主，聚合恰恰把时间结构磨掉了。

一、背景：为什么要在金融做"序列建模表格数据"

Capital One 的 AI Foundations 团队研究员 Nam Nguyen 在 NeurIPS 2024 Expo Talk Panel 上分享了团队过去一两年在"消费银行业务的序列表格建模"上的研究方向。这是一场面向 ML 研究社区的报告，而不是产品发布。

为什么值得研究？讲者先把"金融行业的现实"摆出来：消费银行客户的天然数据形态就是"多个事件流的交织"；"temporal ordering" 在金融场景里不是装饰，是业务；数据规模极大且高度异构；行业现实是"以树模型为主"——但代价是大量手工特征工程，而聚合恰恰把时间结构磨掉了。

Goal: Research general customer understanding through sequential modeling of tabular data.

二、这件事为什么比"序列建模"本身更难

讲者把序列数据分成了三层（NLP / 通用时间序列 / Temporal point process），并强调金融客户事件流属于第三类，但与现有 point process 研究的关键区别是：point process 研究多把事件当作时间轴上的"点"，关心间隔分布；而金融场景里每个点本身是一张多列的表，所以"空间维度"和"时间维度"必须同时建模。

讲者列了四个具体的研究问题：① 非重叠信息（稀疏 NA）如何处理？② 连续值和类别值怎么统一表示？③ 不规则时间戳怎么编码？④ 数据规模与个体差异（亿级客户、分布差异）。

三、社区已有工具盘点：行编码、序列编码、跨表建模

讲者把 2020 年以来"表格序列建模"的相关文献做了一次串讲，按"如何把一行表格变成 embedding"归类：

3.1 行表示：连续 vs 类别，怎么塞进同一个向量空间

  • 量化路线：连续值离散化后走 NLP 的 embedding lookup + row encoder（FT-Transformer / MLP）。优点是简单统一；缺点是连续值精度被牺牲。
  • 保持数值路线：对连续值做缩放 / 分桶 / Fourier 编码，再送入 MLP 或 Fourier 层，让连续值与类别值的 embedding 落在同一空间。

代表工作（2024）：Column-aware Challenge、Sentence-style FeatEner、Bin-based (SCOR)、P2NOM / 生成式（列置换 → rotation invariance）。讲者的总结：2024 年表格研究的爆发点几乎都落在"如何把列名带进 embedding"上。

3.2 序列表示：从行 embedding 到序列 embedding

  • 层级式 (TabuLa 类)：FT-Transformer 编码行 → tabular BERT 在行序列上做 masked LM。
  • 静态/动态分离：static 特征与 dynamic 特征分开编码，再叠 time embedding，送序列 Transformer。
  • 跨异构事件流：每种事件类型单独 FT-transformer + linear 投影到统一空间 → event-level Transformer → 再投影回各自空间。

3.3 Foundation Model for Tabular（2024 趋势）

UNITAB、CM2、TabuLa-BIRDS 等，目标都是在所有表格上预训练超大模型。这些工作的共同短板仍然是没有真正建模时间维度。

四、Capital One 自己的初步探索（最有干货的部分）

讲者明确说他们有意识地从更简单的模型开始——监管行业偏好简单；"more complexity, more things can go wrong"。

4.1 单层 Tokenization + Transformer（替代层级结构）

把所有连续值量化后与类别值构造联合 vocab；每行格式化成 "event_type | amount | merchant | online | …" 的 token 序列；送进一个单层 sequence Transformer。在开源 fraud detection 数据集上，这种简单做法已经超过 SOTA，并能发现新的欺诈模式。

4.2 Causal LM + 标签注入 + Row Permutation

改成 causal LM："给定过去事件，问下一个 event / 下一个属性"。若表里有 fraud 标签，预训练时同时预测下一个事件和fraud 标签，获得 few-shot / in-context 能力。加 row permutation 让模型对缺失特征鲁棒。

4.3 Masked LM + Supervised Contrastive

利用数据里天然存在的"标签型信息"（如 merchant 名称）做有监督对比学习，和 masked LM 一起训练，在 fraud detection 和 loan prediction 上 AUC / AUPRC 都有显著提升。

4.4 分布感知编码（Distribution-aware Functional Encoding）

不同客户的连续值分布差异很大。解法：对每位用户做密度估计 → 转成 Gaussian kernel mixture → 编码成向量 → 作为"分布向量"条件，金额 embedding = 金额值 × 分布向量编码。效果：在分类与回归任务上多数情况下超过所有通用编码器。

五、关键结论与给研究社区的呼吁

讲者在最后留了几组开放问题：表示层面（量化会丢信息，能不能既量化又恢复大小数值差异？金额分布差异怎么编码？）；架构与应用层面（不同 downstream 任务是否需要不同模型？分布偏移、因果建模、可解释性如何兼顾？）；数据层面（最重要的呼吁）：时序表格数据在公开领域几乎不存在，必须要么开放、要么合成大规模时序表格数据。
